# v1.4.0t35：重译恢复与开源部署可靠性

日期：2026-09-27。状态：**代码实现与本地验收完成，待 CI 和线上部署**。本计划以 `v1.4.0t34` 为基线；该版离线测试 1042 通过、1 跳过，7 项公网 RSS 测试及 Ruff 通过。线上首页、`/healthz`、`/admin/` 曾以有效 TLS 返回 200。9 月 27 日刊期的 6 篇译文最终均上线，但一篇约 90 秒的上游响应被上游网关提前截成 504；生产实例的 SUB2API 入口已单独调整为 650 秒。这是实例运维记录，**开源项目不得修改第三方网关，也不得把生产域名或服务器配置当作默认值**。

## 本版边界

- 继续使用现有 Nginx/Certbot、单机单实例、SQLite、Docker Compose 与 systemd；不新增 Caddy/Traefik 模式或队列服务。
- 部署域名只取部署者显式提供的 `ND_DOMAIN`。存量 `NEWS_SITE_URL`、本项目托管的 Nginx 配置与输入域名不一致时停止升级；本版不自动迁移域名。
- 首次签证书失败可完成 HTTP-only 安装，但只提供公开内容读取；Admin、账号、支付和订阅入口不应通过明文开放。已有 HTTPS 站点不得静默降级。
- 未配置联系邮箱时不显示生产实例邮箱；迁移演练构建 URL 必须由 `--site-url` 输入。保留品牌和历史文档中的实例链接，不把它们用作运行默认值。

| 部署验收与回滚 | reload 后、定时器恢复前，本机 SNI + 正常证书校验的 HTTPS GET 要求首页、`/healthz`、`/admin/` 全为 200；所有入口共用结果。失败恢复原 Nginx 配置及原定时器状态。 | reload 失败、状态码错误、证书错配、回滚、首次 HTTP-only 与 Admin 不可访问。严禁使用 `curl -k`。 |
| 翻译一致性 | task、attempt、译文、Admin action 与 provider circuit 的同一次完成在单个 SQLite 事务中提交，原接口继续可用。 | 提交前故障注入整体回滚；成功、失败、租约回收与旧版调用兼容。 |
| 恢复唤醒 | 任务重试与 circuit 探测取共同可执行截止时间；终态失败不空转，混合待重试仍等待。Admin 文件通知即时唤醒；30 秒日历 fallback 先在既有 Admin 容器执行只读 `automation-due`，检查失败则保守启动 worker。 | 过期 probe、混合状态、旧 provider 待办、过期租约；模拟 1 小时空闲状态 0 次空 worker，漏通知后约 30 秒启动到期工作。 |
| DNS 与诊断 | 默认 DNS 在可终止子进程中解析，期限为剩余预算和 10 秒的较小值；仍校验公网 IP 并固定连接。schema 13→14 增加 attempt 的可空 HTTP 状态和安全阶段耗时；`business-status` 增加超期探测、滞留重译动作、近期 504 只读指标。 | 阻塞 DNS 后执行槽可复用；模拟 90/180 秒响应、504、流式响应；隔离备份上迁移、回滚、旧 attempt 保留。日志不含密钥、正文或原始响应。 |
