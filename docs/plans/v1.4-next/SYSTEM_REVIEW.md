## 1. 架构判断

项目的主要短板是业务事实与系统状态之间缺少明确边界：提取成功被视为全文完整，task 成功被视为刊期完成，本地订单取消被视为资金结束，配置保存被视为所有服务已生效，进程健康被视为当天交付正常。

继续采用模块化单体：Python、SQLite、Jinja2、Compose 和 systemd 与当前规模相符。应优先修正这些边界，并减少重复实现；当前没有证据支持迁移微服务、Kafka、Redis、PostgreSQL、向量数据库或重写 HTTP 框架。

以下三点记录扩展审查时的判断，当前以“架构缺陷全部修复、实现保持精简”为原则：

1. 内容链路仍以 R1/R2 为主，但先处理内部发布数据的访问边界；路径唯一性和原文提取保真并入 R1 的交付契约。
2. 正常登录和付款开通链路已有实现；取消后到账、人工权益并发、配置部分生效仍有独立缺口，不能再用“支付认证已有闭环”将其排除。
3. R3 句子重译保留明确交付位置。内容治理、恢复能力和经营闭环分批推进，不把所有改进都设为 R3 的前置条件。

证据分类：**代码事实**表示控制流或数据契约已确认，影响可能仍待发生；**生产事实**表示指定时间的只读观测；**待核实**表示需额外材料；**可选改进**表示尚无证据需要立即建设。后文 P1/P2/P3 是审查时的影响判断，当前是否实施只看第 0 节，不能按旧优先级重新扩大范围。

## 2. 已发现的边界问题

### B1. 内部发布数据与公开资产没有隔离

**P1 / 代码事实，未做线上访问复现。** [publisher.py](../../../src/news_digest/delivery/publisher.py) 的 `write_release_manifest` 将完整刊期序列化到发布目录；[models.py](../../../src/news_digest/models.py):154 的序列化包括双语正文和教学内容。[site_server.py](../../../src/news_digest/site_server.py):936 对未分类为文章的现有文件直接返回，公开文件范围没有显式清单。内部发布数据因此没有与付费阅读相同的授权边界。

最小方案：公开入口仅服务明确的公开页面和资产；内部 manifest、正文快照和诊断文件保存在非公开区域，由 Site/worker 内部读取。公开索引只含实际需要公开的元数据。R1 新增的多刊期 manifest 同样遵守该界限，不能把更多历史原文加入公开数据。

完成依据：用公开资产清单与授权矩阵验证允许返回的内容，覆盖匿名、免费额度、会员、过期会员；内部数据不由通用静态 handler 提供。本轮仅静态审查，没有构造绕过请求。

### B2. 文件解析与权限分类缺少共同的资源身份

**P1 / 代码事实，生产可达条件未核实。** `accounts.py:235` 按请求路径分类，`site_server.py:920` 独立解析文件；目录首页分支在统一目录范围检查之前返回。权限判断、路径规范化和实际文件之间缺少统一契约。

最小方案：先解析为可信资源身份，统一校验发布根目录范围，再决定该资源的公开或会员属性；未知资源默认不公开。所有返回分支共用检查。该修正与 B1 一起完成，不建立另一套权限框架，也不依赖 Nginx 替应用兜底。

完成依据：防御性检查验证所有文件返回分支都经过相同的目录和授权规则，已发布规范链接仍可用。不提供或执行漏洞利用步骤。

### C1. 原文清洗会丢弃短正文，却仍宣称 full

**P1 / 代码事实。** [body.py](../../../src/news_digest/extractors/body.py):54 无条件删除少于 30 字符的段落，提取时排除表格；只要留下两个不同段落，`pipeline.py:114` 就将其标为 `full`。短引语、单独结论等内容可能在翻译前丢失，翻译质量检查看不到这部分损失。

最小方案：保留有正文依据的短段落；只清理明确样板内容。分开表达提取成功、摘要降级与完整性未经核实；保存 extractor version、清洗计数和降级原因。表格是否转换为正文按来源样本决定，不能静默省略后仍承诺全文完整。

完成依据：离线 fixture 覆盖短引语、列表、表格、摘要和正常长文；抽取、清洗与最终原文快照之间可对照。随 R1 固定快照落实，避免永久冻结已被错误删减的输入。

### C2. 页面路径不保证文章唯一

**P1 / 静态风险。** `textutil.py:24` 将标题规整并截断为 60 字符，`pipeline.py:131` 直接作为 slug，`:375` 直接写同名 HTML。不同 URL 可以生成同一路径，导致前一篇被覆盖。现有 manifest 校验会检查最新刊期文章文件存在，但不证明一篇对应一个独立文件，也未覆盖全部历史刊期。

最小方案：文章身份独立于标题；新路径使用稳定 ID 或足够的 hash 后缀，并进行唯一性检查。已发布 URL 保留兼容映射，不能直接批量改 slug。构建从 R1 的固定成员产生全刊期文件清单，并验证路径唯一、成员与产物对应。

完成依据：不同文章同标题、截断后同标题、标题修改及历史重建仍保持身份明确；冲突在发布前被发现。与 R1 一起处理。

### A1. 本地取消订单不等于资金结算结束

**P1 / 代码事实，未证实生产发生异常扣款。** `site_server.py:2191` 只取消本地订单；`storage/db.py:5857` 同时将结算期限设为当前时间。后续付款确认在 `:6173` 因超期被拒绝，Admin 也不再允许普通对账。代码中未见对应的网关关单、异常到账或退款闭环。

最小方案：分开保存购买意图、网关资金事实和权益结果。用户取消不抹去待结算责任；只有网关确认关闭或经过明确核对，才收口结算身份。验签且核对订单、金额、交易唯一性的迟到到账进入异常单，再按运营规则补权益或退款。不能只取消超时检查，也不能直接把所有迟到回调认作成功。

完成依据：取消与到账交错、回调迟到、重复通知、网关状态不确定均保留可解释的资金事实；同一付款只增加一次权益。用本地网关替身验证，不以真实扣款作常规测试。

### A2. 人工赠送可能覆盖并发支付新增的权益

**P1 / 静态并发风险。** `preview_server.py:1587` 读取旧到期时间并在 HTTP 层计算新值，`storage/db.py:5132` 再独立写入。中间若支付回调或卡密兑换增加权益，人工操作可能使用旧值覆盖它。支付与卡密自身已有事务保护。

最小方案：将“增加 N 天”“设置到期日”“清空权益”定义为不同业务命令；增加时长在统一权益事务内读取和累加，明确 plan 合并规则，关联操作 ID、操作者和原因。保留 `users` 当前权益快照，不要求全量 event sourcing。

完成依据：人工赠送与支付/兑换交错时不丢时长，重复同一命令不重复赠送；显式设置到期日需要检测旧值变化。与 A4 的审计记录一起交付。

### O1. 配置保存跨文件和数据库，失败时可能部分生效

**P1 / 代码事实，未证实现场配置已分裂。** `preview_server.py:1793` 先保存源配置文件，再改 DB active config、写 Site 投影，最后提交 DB；rollback 无法撤销前面已替换的文件。SMTP 保存也涉及多个文件。现有单文件原子替换不能保证跨存储一致。

最小方案：为配置确定单一权威及 revision，衍生投影可以重建。记录 desired/applied revision 和错误；只有完整准备且确认可读取的配置才成为 active，业务订单引用对应配置身份。失败后恢复器按权威 revision 修复投影，而不是猜哪份文件最新。保留密钥文件权限和已有未结算订单的配置绑定。

完成依据：文件写入、投影和 DB 提交中断后，能够明确显示哪一版生效并恢复一致；页面“保存成功”不提前于生效确认。网络测试不放在 DB 事务中。

### O2. 离线备份与恢复说明遗漏 Site 写入者

**P1 / 文档事实。** `deploy/README.md:433` 的整卷停写前提和 `:460` 的恢复说明只要求停止 Admin/worker；`docs/OPERATIONS.md:124` 也只列 fetch/translate/send-email。Site 实际会写账号、订单、会话，并持续消费 account outbox。按现有说明操作不能建立全库停写条件。

最小方案：日常数据库快照沿用现有 SQLite online backup；只有离线整卷归档和覆盖恢复才要求停止所有写入者，包括 Site。恢复后核对备份之后产生的外部资金和邮件事实，不能因库回退而重新扣权益或重发邮件。bootstrap 的 online backup 已有 WAL 一致性与校验，不应删除。

完成依据：恢复手册列出全部实际写入者，隔离恢复能核对用户、订单、刊期、投递和配置；全库恢复前确认没有残存写进程。不能只靠脚本文本包含某个 unit 名证明恢复安全。

## 7. 职责参考

| 模块 | 负责的事实与命令 | 关键边界 |
|---|---|---|
| Ingestion / Editorial | 来源许可范围、抓取、提取、候选、选题理由、刊期快照 | 抽取成功不证明全文；候选变化不改已选成员 |
| Translation / Revision | 当前任务、provider attempt、自动单句修复、完整接受结果 | 教学降级不拖垮正文；修复只处理可定位失败，提交检查 source 与任务所有权 |
| Publication / Access | 私有发布 manifest、公开资源清单、会员读取决策 | 内部内容不由通用静态服务公开；文章身份不依赖标题 |
| Accounts / Entitlements | 账号确认、会员命令、权益快照及变更记录 | 所有加时长操作共用事务；长期任务不占认证请求 |
| Payments / Settlement | 购买意图、网关事实、待核对订单、异常到账、退款引用 | 界面过期或取消不抹去资金责任；权益按付款幂等应用 |
| Delivery | 偏好、资格、正式投递、验证码 outbox 各自结果 | 退订始终有效；零目标、失败和 unknown 语义不同 |
| Configuration / Operations | 权威配置 revision、生效投影、备份及业务状态 | 单文件原子写不冒充跨存储事务；恢复覆盖全部写入者 |

这是分析职责的参考，不是模块拆分任务。当前只新增内容一致性、自动修复及各架构缺陷确需的数据，优先扩展现有 task/attempt/run。人工候选审批存储、来源登记和产品扩展不作为前置；权益、配置、备份、健康与投递所需的最小架构记录仍必须按第 0 节分批完成。
